## 2. 产品定位与 V1.0 目标

PocketJoy（口袋快乐）是一款把上班时间转化为即时正反馈的移动端情绪工具。它通过大口袋、金币掉落、轻量音效与震动反馈，让用户在工作间隙获得"我正在积累快乐"的感受。

### 2.1 V1.0 必须完成

- 首次进入时完成税后月薪设置，并可设置或修正当前月工作天数。
- 首页以一个"大口袋"为核心视觉，承载金币掉落、口袋弹跳、呼吸光效和趣味文案。
- 按随机间隔触发金币掉落，并按工资分薪与实际间隔计算本次金币数量。
- 首页只展示金币、金条、工作时长与运行状态，不展示真实金额、货币符号或月薪。
- 提供暂停/继续、打卡下班、静音/震动、随机间隔设置、清除本地数据等基础能力。
- 所有数据仅保存在设备本地，V1.0 不登录、不联网同步、不云备份。

### 2.2 V1.0 不做

- 职场社交、双人同频、匿名漂流瓶、周报/月报、年度回顾。
- Apple Watch、手环等智能硬件联动。
- 复杂日历与法定节假日自动识别。V1.0 默认按当月周一至周五计算，可由用户手动修正。

## 3. 技术栈建议

> **推荐方案**：若团队没有既定技术栈，建议 V1.0 使用 Flutter 开发正式移动端工程。它适合高质量自定义动画、跨端一致 UI、本地存储、音效与震动反馈，也便于后续接 Rive/Lottie 动效资产。

| 方案 | 适用情况 | 建议 |
|------|----------|------|
| Flutter | 重视动效质感、iOS/Android 一致性、长期作为正式 App 维护 | 主推荐 |
| React Native + Expo | 团队已有 React 经验，优先快速迭代和原型验证 | 可作为备选 |
| Swift + Kotlin | 需要极致原生能力且有双端团队 | MVP 不建议，成本较高 |
| WebView / H5 | 只做营销页或临时演示 | 不建议作为正式移动端 App 首发 |

**Flutter 推荐模块**：
- UI：Flutter Material/Cupertino 自定义主题
- 动效：Rive 或 Lottie
- 敏感字段本地存储：`flutter_secure_storage`
- 普通设置：`shared_preferences`
- 统计流水：Hive / SQLite
- 音效与震动：平台能力封装
- 本地通知：`flutter_local_notifications`，触发前请求授权

## 5. 首页定义

首页核心视觉定义为一个"大口袋"。它可以是钱袋、糖袋或带金色束口的口袋形象，但语义必须是"把快乐和金币装进口袋里"。首页不是工资账单页，不做真实金额展示。

### 5.1 应用状态机 **[基于 PRD Section 5 整理]**

```
                    ┌──────────────┐
                    │  未设置工资   │
                    └──────┬───────┘
                           │ 保存工资成功
                           ▼
                    ┌──────────────┐
          ┌────────│   运行中     │◄────────┐
          │        └──┬───┬───┬──┘         │
          │           │   │   │            │
          │    暂停    │   │ 下班   退后台  │
          │           │   │   │            │
          ▼           ▼   ▼   ▼            │
   ┌──────────┐ ┌──────────────┐           │
   │  暂停态   │ │  下班态       │   前台恢复 │
   └────┬─────┘ └──────────────┘           │
        │ 继续                  次日自动     │
        └──────────────────────────────────┘
```

| 状态 | 描述 | 进入条件 | 口袋动画 | 计时 | 掉落 |
|------|------|----------|----------|------|------|
| `unset` | 未设置工资 | 首次打开 / 清除数据后 | idle + 微弱呼吸 | ❌ | ❌ |
| `running` | 正常运行 | 已设置工资且未暂停/下班 | breathing 循环 | ✅ | ✅ |
| `paused` | 暂停中 | 用户点击暂停 | paused（微暗，动效最低） | ❌ | ❌ |
| `offWork` | 已下班 | 用户点击打卡下班 | idle（安静） | ❌ | ❌ |
| `background` | 退到后台 | App 进入后台 | 动画暂停 | ❌ | ❌ |

**状态转换规则：**

| 从 → 到 | 触发事件 | 说明 |
|----------|----------|------|
| `unset` → `running` | 用户完成工资设置 | 进入运行态首页 |
| `running` → `paused` | 用户点击暂停 | 显示"口袋休息中" |
| `running` → `offWork` | 用户点击打卡下班 | 当日停止掉落 |
| `running` → `background` | App 退到后台 | 暂停动画与计时 |
| `paused` → `running` | 用户点击继续 | 重新生成种子间隔，不补发 |
| `background` → `running` | App 回到前台 | 重新生成种子间隔，不补发 |
| `offWork` → `running` | 用户手动重新开始 / 次日自动 | 新的一天重新开始 |
| `running` → `unset` | 用户清除数据 | 回到初始化页 |
| `paused` → `background` | 暂停状态下退后台 | 保持暂停态 |
| `background` → `paused` | 暂停状态下回到前台 | 保持暂停态 |



### 5.2 未设置工资金额状态

- 画面中央展示静态大口袋，口袋保持轻微呼吸光效，不掉金币。
- 主文案：「先告诉口袋你的工资，让它开始为你攒快乐吧」
- 主按钮：「设置工资」
- 底部统计区显示占位态，例如"今日金币 --""本月金条 --"，不出现真实金额。
- 用户完成保存后进入运行态首页。

### 5.3 运行态首页

| 区域 | 内容 | 交互/规则 |
|------|------|-----------|
| 顶部状态 | 已工作时长、当前运行状态、设置入口 | 工作时长按前台运行时间累加；后台暂停 |
| 中央视觉 | 大口袋、金币、柔和光晕 | 触发时金币抛物线掉入口袋，口袋轻微弹跳 |
| 情绪文案 | 随机触发，详见 §5.3.1 情绪文案池 | 淡入 300ms、停留 2s、淡出 300ms |
| 统计区 | 今日金币、本月金条 + 剩余金币 | 不展示真实金额；1000 金币 = 1 根金条 |
| 操作区 | 暂停/继续、打卡下班、静音/震动 | 打卡下班后当日停止自动掉落，次日可重新开始 |

#### 5.3.1 情绪文案池

**触发规则**：按本次掉落金币数量分三档，各档内随机抽取一条文案。文案淡入 300ms、停留 2 秒、淡出 300ms。

| 档位 | 金币范围 | 基调 |
|------|----------|------|
| 小额 | 1-30 | 轻快、治愈、陪伴 |
| 中额 | 31-100 | 职场幽默、温暖 |
| 大额 | 100+ | 奖励感、共鸣、小确幸 |

**小额文案池（1-30 金币）**：
1. 「叮！一颗快乐入账 ✨」
2. 「这秒没白过」
3. 「叮当！口袋又重了一点点」
4. 「又攒到一小口甜」

**中额文案池（31-100 金币）**：
5. 「摸鱼也是生产力 🐟」
6. 「把上班时间折成糖纸 🍬」
7. 「别急，快乐要一粒一粒攒」
8. 「今日进度条又往前跳了一格」

**大额文案池（100+ 金币）**：
9. 「老板不知道，但口袋知道」
10. 「金灿灿的，像周五下午四点 🌇」
11. 「这间隔，值了」
12. 「哗啦——口袋发出满足的声响」

**防重复**：连续两次不掉落同一文案。如同一档位文案池耗尽，则跨档抽取。

### 5.4 暂停、下班与后台

- **暂停**：停止计时与金币掉落，首页显示"口袋休息中"。
- **继续**：从当前时间重新启动下一次随机间隔，不补发暂停期间金币。
- **打卡下班**：结束当日计时，不再触发金币掉落；用户可手动重新开始。
  - 「手动重新开始」入口：下班后首页操作区「打卡下班」按钮替换为「重新开始」，点击后进入 running 状态，重置今日计时与掉落序列。
- **退到后台**：V1.0 暂停动画与计时，不进行后台金币计算；回到前台后重新排定下一次掉落。
- **跨天**：今日金币与工作时长在本地日期变更时重置。App 前台运行时若检测到跨天（系统时间日期变更），**立即**重置今日计时器与今日金币，不等待退后台。本月金币保留到月底。
- **系统时间回拨**：检测到系统时间回拨超过 1 分钟时，立即暂停金币掉落并弹 toast：「检测到系统时间异常，金币掉落已暂停。请校正系统时间后继续。」用户校正时间后可手动恢复运行。

## 6. 薪资与金币计算规则

### 6.1 输入项

| 字段 | 规则 | 默认/校验 |
|------|------|-----------|
| 税后月薪 | 用户输入，作为本地计算基数 | 必填，正数；保存后首页不显示 |
| 当前月工作天数 | 默认按当月周一至周五估算，允许用户手动修正 | 必填，1-31 的整数 |
| 每日工作小时 | V1.0 固定按 8 小时计算 | 暂不开放自定义 |
| 随机间隔范围 | 最小间隔与最大间隔，单位分钟 | 默认 15 分钟至 5 小时；最小值必须小于最大值 |

### 6.2 计算公式

```
每分钟工作分薪 = 税后月薪 / 当前月工作天数 / 8 / 60
本次掉落金币 = round(每分钟工作分薪 × 本次实际间隔分钟数)
```

**展示换算**：1 个本地货币单位 = 1 金币；1000 金币 = 1 根金条。首页只展示金币与金条，不展示货币单位。

**边界规则**：计算结果大于 0 但四舍五入为 0 时，按 1 金币展示。累计金币只保留整数。

### 6.3 计算示例

| 示例 | 计算 |
|------|------|
| 月薪 20000，当前月 22 个工作日 | 每分钟工作分薪 = 20000 / 22 / 8 / 60 ≈ 1.89 |
| 间隔 15 分钟 | 本次掉落 ≈ 28 金币 |
| 间隔 300 分钟（5 小时） | 本次掉落 ≈ 568 金币 |
| 累计 3240 金币 | 展示为 3 根金条 + 240 金币 |

## 7. 随机掉落间隔算法

V1.0 使用"随机种子 + 倍率序列"的掉落间隔。用户可设置随机间隔范围，例如 15 分钟至 5 小时。第一次间隔在范围内随机生成；后续间隔按 3 倍、1/2 倍交替计算。

### 7.1 规则定义

- 配置项：`minIntervalMinutes`、`maxIntervalMinutes`，默认 15 和 300。
- 首次运行或重新开始时：在 `[min, max]` 内随机生成 seedInterval。
- 第二次间隔：previousInterval × 3。
- 第三次间隔：currentInterval × 1/2。
- 之后按 ×3、×1/2 循环交替。
- 若计算结果超过 max，则使用 max；若低于 min，则使用 min。
- 若连续两次命中同一个边界值，为避免节奏僵硬，下一次重新在 `[min, max]` 内随机生成种子间隔。
- 用户暂停、下班、退后台后恢复，均重新生成下一次种子间隔，不补算已暂停时间。

重新随机种子后，倍率序列 index 重置为 0（即下一轮重新从 ×3 开始），避免连续边界命中导致的节奏僵化。

### 7.2 伪代码

```python
seed = random(minInterval, maxInterval)
multipliers = [3, 0.5]
index = 0  # 重新随机种子后重置为 0

candidate = previousInterval * multipliers[index % 2]
nextInterval = clamp(candidate, minInterval, maxInterval)

if sameBoundaryHitTwice:
    nextInterval = random(minInterval, maxInterval)
    index = 0  # 重新随机后重置
```

## 8. 本地数据与状态管理

### 8.1 数据模型

| 数据项 | 类型 | 默认值 | 用途 | 存储方式 |
|--------|------|--------|------|----------|
| `salaryAfterTax` | double | null | 计算每分钟工作分薪 | `flutter_secure_storage`（敏感） |
| `currentMonthWorkdays` | int | 当月 Mon-Fri 天数 | 当前月工作天数 | `shared_preferences` |
| `dailyWorkHours` | int | 8 | 每日工作小时（V1.0 固定） | 常量 |
| `intervalMin` | int | 15 | 随机间隔下限（分钟） | `shared_preferences` |
| `intervalMax` | int | 300 | 随机间隔上限（分钟） | `shared_preferences` |
| `todayCoins` | int | 0 | 今日累计金币 | Hive / SQLite |
| `monthCoins` | int | 0 | 本月累计金币 | Hive / SQLite |
| `todayWorkSeconds` | int | 0 | 今日已工作时长（秒） | Hive / SQLite |
| `isPaused` | bool | false | 是否暂停 | 内存 + `shared_preferences` |
| `isOffWork` | bool | false | 是否已下班 | 内存 + `shared_preferences` |
| `soundEnabled` | bool | true | 音效开关 | `shared_preferences` |
| `hapticEnabled` | bool | true | 震动开关 | `shared_preferences` |
| `lastTriggerAt` | DateTime? | null | 上次掉落时间戳 | 内存（仅前台有效） |
| `nextInterval` | int? | null | 下次掉落间隔（分钟） | 内存（仅前台有效） |
| `multiplierIndex` | int | 0 | 当前倍率序列位置 | 内存（仅前台有效） |
| `lastBoundaryValue` | int? | null | 上次命中的边界值 | 内存（仅前台有效） |

### 8.2 字段校验规则

| 字段 | 校验 |
|------|------|
| `salaryAfterTax` | > 0，≤ 10,000,000 |
| `currentMonthWorkdays` | 1-31 整数 |
| `intervalMin` | ≥ 1，< `intervalMax` |
| `intervalMax` | ≤ 1440（24h），> `intervalMin` |

### 8.3 App 启动时的状态恢复逻辑

```
App 启动 →
  if salaryAfterTax == null → unset 状态
  else if 当前日期 != lastActiveDate → reset todayCoins, todayWorkSeconds, 设为 running
  else if isOffWork == true → offWork 状态
  else if isPaused == true → paused 状态
  else → running 状态
```

`lastActiveDate` 存储于 `shared_preferences`，用于启动时判断是否跨天/跨月。

### 8.4 跨天/跨月自动处理

- 检测到日期变更时：`todayCoins = 0`，`todayWorkSeconds = 0`
- 检测到月份变更时：`monthCoins = 0`
- V1.0 不做历史记录明细，但数据模型预留 `yesterdayCoins` 和 `lastMonthCoins` 字段（均 int，默认 0），在跨天/跨月时写入后清零当日/当月计数。UI 暂不展示。

## 10. 视觉方向与资产规范

### 10.1 什么是暗色治愈风

暗色治愈风不是强刺激的夜店霓虹，也不是纯黑压抑界面。它的核心是低亮度深色背景、柔和边缘光、暖金主视觉、慢节奏呼吸动效和清晰可读文字。用户长时间打开时不刺眼，但每次金币掉落仍然有"眼前一亮"的奖励感。

### 10.2 视觉原则

- **背景**：深黑或深灰为主，避免大面积高饱和紫粉色；可以使用低透明度蓝绿/金色柔光。
- **主视觉**：一个质感明确的大口袋，占据首页视觉中心，默认安静，触发时有弹跳与金币吸入。
- **金币与金条**：金币用于即时奖励，金条用于累计成就；1000 金币合成 1 根金条。
- **动效**：慢呼吸常驻，金币掉落短促有反馈；避免高频闪烁、强眩光和长时间满屏烟花。
- **文案**：职场幽默可以轻松，但不嘲讽用户；鼓励、陪伴、轻微玩笑优先。

### 10.3 资产规范说明

视觉资产规范是设计与开发之间的交付约定，不要求现在一次性定稿。它需要说明素材类型、尺寸、格式、命名、动效时长和性能预算，保证后续替换素材时不改业务代码。

| 资产 | 建议格式 | 开发要求 |
|------|----------|----------|
| 大口袋主视觉 | Rive/Lottie 或透明 WebP/PNG 序列 | 至少包含 idle、breathing、receive、paused 四种状态 |
| 金币 | 矢量/Lottie 或透明 PNG | 支持抛物线、旋转、缩放与进入口袋后的消失 |
| 金条 | 透明 WebP/PNG | 用于累计统计，不需要频繁动画 |
| 背景光效 | 代码渐变 + 模糊光晕优先 | 不要用大体积视频背景；光效周期 4-6 秒 |
| 图标 | SVG 或平台图标库 | 用于设置、静音、震动、暂停、下班 |
| 音效 | AAC/MP3，短音频 | 默认低音量，可关闭；提供仅震动模式 |

> 详细资产清单见 [`PocketJoy_V1.0视觉资产交付清单.md`](./PocketJoy_V1.0视觉资产交付清单.md)

## 12. 隐私合规说明

> **隐私底线**：工资属于敏感个人信息。V1.0 不建立账号、不上传、不共享、不备份、不做云同步；所有计算和展示均在本机完成。

- **数据最小化**：只保存完成核心功能所必需的数据，包括税后月薪、工作天数、间隔设置、金币统计和音效/震动偏好。
- **本地存储**：敏感字段使用系统安全存储；普通设置和统计可使用本地数据库或偏好存储。
- **权限最小化**：V1.0 不申请定位、通讯录、相册、麦克风等无关权限。通知、音效、震动若需系统授权，应在用户触发相关功能前说明用途。
- **首页脱敏**：首页、锁屏预览、系统通知文案不得展示真实工资、真实金额或货币符号。
- **清除数据**：设置页必须提供"清除本地数据"能力，清除后回到未设置工资的首页状态。
- **第三方 SDK**：V1.0 默认不接入广告、画像、云统计 SDK。若后续接入崩溃分析，禁止上报工资、金币明细或可识别个人身份的信息。
- **隐私政策**：应用上架前需要提供简洁隐私政策，明确说明数据本地处理、权限用途、清除方式和不上传承诺。

## 13. 通知系统

V1.0 使用本地通知（不经过服务器）。所有通知文案不出现真实工资金额或货币符号。

| 通知类型 | 触发时机 | 标题 | 正文 | 频率限制 |
|----------|----------|------|------|----------|
| 暂停提醒 | 暂停超过 2 小时 | 「口袋在等你哦」 | 「已经休息一阵子了，要不要让口袋继续掉糖？」 | 暂停期间最多 1 次 |
| 金币里程碑 | 今日金币累计达到 500 / 1000 / 2000 | 「叮！今日里程碑达成 ✨」 | 「今天的快乐已经装了不少，打开看看吧」 | 每日最多 3 次（每档 1 次） |
| 下班提醒 | 工作日累计满 8 小时 | 「今天辛苦了 🌙」 | 「口袋已经装得满满的，记得打卡下班哦」 | 每日 1 次 |
| 金条达成 | 本月累计合成金条（每 5 根触发一次） | 「金条又多了！」 | 「本月已经攒了 N 根金条，进度喜人」 | 每月最多 2 次 |

**注意事项**：
- 通知不出现真实工资金额或货币符号
- 通知权限在首次可能触发通知时请求授权（如首次暂停后），弹窗说明用途：「PocketJoy 会在金币里程碑和下班时发送轻提醒，帮助你不错过攒快乐的时刻」
- 静音模式不影响通知（通知有独立的系统设置）
- 用户在设置页可关闭所有通知（独立于系统通知设置的应用内开关）

## 14. 验收标准

| 场景 | 验收点 |
|------|--------|
| 首次打开 | 未设置工资时首页显示大口袋与"填写工资金额"入口，不启动掉落计时 |

## 16. 动画优先级与冲突处理

| 场景 | 规则 |
|------|------|
| 金币掉落中 + 触发金条合成 | 当前掉落动画播完后立即触发金条合成动画（排队，不叠加） |
| 任何动画中 + 用户点击暂停 | 立即中断当前动画，口袋进入 paused 态（优先响应用户操作） |
| 金币掉落中 + 又到下一次掉落时间 | 排队等待：当前掉落播完后，按正常间隔触发下一次；不跳过、不累加 |
| 金条合成中 + 触发金币掉落 | 金条合成优先播完，掉落排队（金条达成感 > 常规掉落） |
| 连续排队超过 2 个掉落 | 丢弃最早排队的掉落，仅保留最近 2 个待播放（防止积压） |
| 动画播放中 + App 退后台 | 立即暂停所有动画，回到前台后不恢复未完成的动画 |
